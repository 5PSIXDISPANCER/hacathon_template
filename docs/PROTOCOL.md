# Спецификация акустического протокола

## Цели

Передача произвольных файлов через акустический канал (микрофон и колонки) с гарантией целостности данных и возможностью восстановления потерянных пакетов.

## Физический уровень

### Параметры сигнала
- **Частота дискретизации (Fs)**: 44 100 Гц (может переключаться на 48 000, 16 000, 24 000)
- **Формат аудио**: 32-bit float (paFloat32)
- **Каналы**: монофонический (1 канал)
- **Разрядность**: int16 при записи/воспроизведении

### Спектр и модуляция
Используется M-FSK (Multi-Frequency Shift Keying) с параметрами:
- **Количество частотных каналов**: 4
- **Базовая частота (F_BASE)**: 500 Гц
- **Шаг между каналами**: 400 Гц
- **Диапазон каналов**: 500 Гц - 1700 Гц

Каждый канал поддерживает 16 тональностей (0-15):
- **Шаг тональностей (TONE_STEP)**: 25 Гц
- **Диапазон частот в канале**: F_BASE + k*CHANNEL_SPACING + [0..15]*TONE_STEP

Пример для канала k=0: 500 + 0*400 + [0..15]*25 = 500-875 Гц
Пример для канала k=3: 500 + 3*400 + [0..15]*25 = 1700-2075 Гц

## Формат передачи

### Структура пакета (frame)

```
[Преамбула: 4 байта] [Заголовок: 2 байта] [Полезная нагрузка: 64 байта] [ECC: 16 байт]
     0xDEADBEEF         Frame ID             Данные файла          Рид-Соломон
```

**Итого**: 4 + 2 + 64 + 16 = 86 байт на пакет

### Кодирование уровня символов

1. Весь пакет (86 байт) преобразуется в nibbles (полубайты):
   - 86 * 2 = 172 nibble
   
2. Nibbles разбиваются на символы по 4 (K=4):
   - 172 / 4 = 43 символа (без padding'а)
   
3. Если остаток: дополняется нулями до кратности 4

### Кодирование одного символа

Каждый из 4 nibbles символа кодируется в отдельном частотном канале:
- Nibble 0 → Канал 0 → частота F_0(n)
- Nibble 1 → Канал 1 → частота F_1(n)
- Nibble 2 → Канал 2 → частота F_2(n)
- Nibble 3 → Канал 3 → частота F_3(n)

Все 4 синусоиды суммируются и подаются на микрофон/колонки одновременно.

### Длительность символа

- **SYM_DUR**: 80 мс
- **Количество семплов на символ**: 44 100 * 0.08 = 3 528 семплов

### Окно затухания

Каждый символ применяет fade-in/fade-out окно:
- **Длина fade**: 2 мс (88 семплов)
- Первые 88 семплов: linspace(0, 1)
- Последние 88 семплов: linspace(1, 0)
- Промежуток: единичное окно

Цель: уменьшить клики на границах символов.

## Установление и завершение передачи

### Передача (отправка)

1. Добавить **1 сек тишины** в начало сигнала (для стабилизации АУЭ микрофона)
2. Закодировать все пакеты файла
3. Между пакетами вставить **5 мс тишины**
4. Добавить **1 сек тишины** в конец

### Приём (запись с микрофона)

Таймауты:
- **total_timeout = 60 сек**: максимальное ожидание первого чанка
- **silence_timeout = 15 сек**: максимальное время молчания между чанками после получения первого

Алгоритм:
1. Запустить запись на микрофон
2. Буфер за буфером декодировать ggwave-чанки
3. При получении чанка → сбросить счётчик молчания
4. Собирать чанки в словарь по индексу
5. Выход, когда получены все чанки (len(chunks) == total_expected)

## Синхронизация

### Обнаружение начала пакета (sync acquisition)

Преамбула `0xDEADBEEF` = 4 байта = 8 nibbles, требующие 2 символа M-FSK.

Алгоритм поиска (soft-decision):
1. Вычислить soft-энергии для всех 4 каналов и всех 16 тональностей каждого символа
2. Для каждого возможного начального положения: вычислить скор совпадения с преамбулой
3. Выбрать положение с максимальным скором

Soft-энергия канала k для символа i:
```
E[i, k, tone] = (I²_i,k,tone + Q²_i,k,tone)
```
где I, Q — квадратурные компоненты за этот символ на этой частоте.

### Frame ID синхронизация

После преамбулы идёт 2-байтовый Frame ID (big-endian). Используется для порядка чанков.

## Ошибки и восстановление

### Код Рида-Соломона (RS)

- **Кодер**: `reedsolo.RSCodec(16)` → 16 ECC-символов (bytes)
- **Мощность коррекции**: до 8 ошибок на пакет (или 16 erasures, если известны позиции)
- **Галуа-поле**: GF(256) по умолчанию

Процесс:
1. [Заголовок(2) + Данные(64)] → RS encode → добавить 16 ECC байт
2. При приёме: RS decode → восстановить исходные 66 байт или выбросить пакет

### Обработка потерянных пакетов

- **Если потеря одиночного пакета**: заполнить нулями (b'\x00' * PAYLOAD_PER_FRAME)
- **Если потеря нескольких подряд**: результирующий файл будет повреждён, но UI сообщит об ошибке распаковки

## Совместимость

### Версионирование

Protocol ID в ggwave: `protocol_id = 1`

Если нужна совместимость с будущими версиями — использовать другой protocol_id.

### Частотные диапазоны

Основные частоты:
- F_MIN = 500 Гц (канал 0)
- F_MAX = 500 + 3*400 + 15*25 = 2075 Гц (канал 3, тон 15)

Полоса, необходимая для передачи: ~500 Гц (от 500 до 2075 Гц).

Рекомендуется фильтрация:
- Нижний предел: F_BASE - 50 = 450 Гц
- Верхний предел: F_MAX + 50 = 2125 Гц

## Пример

### Передача текста "Hello" (5 байт)

1. **Сжатие**: создать 7z-архив → предположим, 200 байт
2. **Разбиение на чанки**: 200 / 80 = 3 ggwave-чанка
3. **Для каждого ggwave-чанка**:
   - Индекс (0, 1, 2), Total (3) → payload = "00000/00003:base64_data_0"
   - Кодировать в волну
4. **Для каждой волны**:
   - Обернуть в M-FSK пакет (Preamble + FrameID + Data + ECC)
   - Модулировать в сигнал 44.1 кГц
5. **Передача**:
   - [1 сек тишины] [пакет 0] [5 мс] [пакет 1] [5 мс] [пакет 2] [1 сек тишины]
   - Проиграть через Stream()
6. **Приём**:
   - Прослушивать микрофон
   - Декодировать M-FSK пакеты
   - Извлечь и decodeChunk() ggwave-данные
   - Собрать архив
   - Распаковать → получить исходные 5 байт
