# Ограничения решения

## Поддерживаемые условия

- **Сжатие файлов**: до 10 МБ (оптимально до 1-2 МБ)
- **Форматы**: любые файлы, выбор формата в UI ограничен `.jpg` и `.txt`
- **Аудио-устройства**: требуются рабочие микрофон и колонки
- **Тишина в помещении**: минимальный фоновый шум для надёжной передачи
- **Расстояние**: звуковой канал на расстояние до 5-10 метров в помещении

## Известные ограничения

1. **Пропускная способность**: 
   - Реальная скорость передачи: ~200-400 байт/сек (в зависимости от помех)
   - Файл 1 МБ передаётся ~2500-5000 секунд (~42-83 минуты)

2. **Надёжность в помещении с шумом**: 
   - Фоновый шум (кондиционер, люди, автомобили) вызывают потерю чанков
   - Код Рида-Соломона восстанавливает до 16 ошибок на пакет, но при интенсивных помехах этого недостаточно

3. **Синхронизация времени**:
   - Нет синхронизации часов между устройствами
   - Таймауты жёсткие (60 сек на первый чанк, 15 сек на молчание)

4. **Конкурентность**:
   - UI заморозится, если не использовать потоки (реализовано через `threading`)
   - Не поддерживается одновременная отправка и приём

5. **Размер чанка зафиксирован**:
   - `CHUNK_RAW_SIZE = 80` байт (до base64)
   - Изменение требует перекомпиляции

6. **Частота дискретизации**: 
   - Жёстко установлена на 44.1 кГц
   - Некоторые микрофоны могут не поддерживать эту частоту

7. **Параметры M-FSK не оптимизированы**:
   - `SYM_DUR = 80 мс` может быть слишком велико для чистого сигнала
   - Регулировка требует пересчёта всех вспомогательных параметров

## Что не входит в текущую версию

- **Шифрование**: данные передаются открытым текстом
- **Аутентификация**: нет проверки подлинности отправителя
- **Сжатие в реальном времени**: архив создаётся полностью перед кодированием
- **Возобновляемость передачи**: если разорвалась передача, нужно начинать заново
- **Выбор устройства**: используется устройство по умолчанию (нельзя переключиться, если подключено несколько микрофонов/колонок)
- **Логирование и мониторинг**: нет логов, невозможно отследить, где произошла ошибка

## Риски демонстрации

1. **Внешние помехи**: 
   - Демонстрация в шумном помещении (офис, конференция зал) → высокий процент потери пакетов
   - Решение: выбрать тихое место

2. **Отличия аудио-устройств**:
   - Разные микрофоны имеют разные чувствительности и АЧХ
   - На одних устройствах передача может работать, на других нет
   - Решение: предварительно протестировать оборудование

3. **Синхронизация**:
   - Если устройство подключит микрофон с задержкой (> 60 сек) → придётся заново начинать
   - Решение: включить микрофон ДО начала передачи

4. **Потеря критических пакетов**:
   - Если потеряны пакеты в конце архива → распаковка может не сработать
   - Решение: дублировать концевые пакеты

## Дальнейшее развитие

- Адаптивная регулировка параметров модема (частота, длительность символа) на основе качества канала
- Интерактивный выбор аудио-устройства
- Шифрование AES-256
- Возобновляемость передачи (контрольные точки)
- Поддержка нескольких файлов в одной передаче
- Оптимизация под мобильные платформы (iOS, Android)
- WebRTC для передачи через интернет
